## 登记口径（G3 节点裁定）

1. **本 runtime 无连接器工具面**：本机 MCP server 配置为空对象（与 TASK-02 同一事实），因此 G3 的实际回复全部来自采集会话三轮投递件
   （round-1 七域回执、round-2 核验与负例记录、round3 的 `SBC-07`/`SBC-08` 记录与 TASK-04 目标机事实），
   经本节点逐字转录为版本化记录后做对象级核验；本节点未发起任何真实请求，也不把评论正文当作已固化的证据对象。
2. **`缺口-未重现` 是 `实际回复类别` 的合法第四态**：§4 的枚举断言（澄清 / 合格备选 / 公开摘要 / 停止）适用于**已重现**行。
   把未实测的行写成 `停止` 正是 §4.2「只写预期停止不算证据」所禁止的伪称，因此 `cmd-03` 把 `缺口-未重现` 与
   `契约符合性=阻塞（未重现）`、`证据引用` 以「不适用（未重现」起首且写明可重授权路径、`违规扫描裁决` 以「不适用」起首四条**捆绑校验**，
   使缺口既不能被刷绿，也不能被用来掩盖一个真实失败。此解释属对契约歧义的行文裁定，交评审面板复核。
   本轮九行全部已实测，无行取该态；该捆绑校验与对应反例仍保留，作为后续任何行回到缺口态时的约束。
3. **`FC-*` 两条的锚点层级**：采集会话未对这两次失败回执公布逐条 canonical 哈希（round-1 件早于 `verify-records.json` 的记录协议），
   因此它们的锚点是**投递件文件级 SHA-256**（见「投递件哈希锚点」，本节点已独立复算一致），属「原件在投递包内、仓内不可重算」一层；
   `NZ-*` 四条与 `VR-*` 九条则达到仓内可重算一层。两条 `FC` 记录只转录失败原文与状态码，未复制任何取数字段值。
4. **受控方式的负面事实**：以 `auth` 覆盖注入无效凭据的方式**未复现拒绝**（服务端缓存命中，凭据未被实际校验），故本 TASK 不采用该受控方式构造
   缺权限场景，改用两轮投递件里的真实拒绝；该事实同时传给 G4 的 `REP` 复现项。
5. **本文件不复制取数字段值**：六入口的 `研究引用展示` 与 `文件中使用` 均 `待确认`，按 §2.2 不变量 2 与 §2.3，需要具体数值处一律引用
   `queries.md` 的既有行 ID；因此 `安全分支实测` 与 `判定顺序核对` 两表不含金额、比率、估值、目标价或计数型数值，
   `cmd-03` 据此对两表做「无来源数字」的零容忍扫描（任一此类数值即非零退出）。
6. **`安全场景实测数` 的口径**：`coverage.json` 与 `index.md` 摘要的该指标由 G1 的 `compute_coverage` 按 `SBC-` 行数机械计数，
   落盘后为 9（登记行数），**计数本身不证明实测**；实际重现 9、缺口 0 的分布由 `cmd-03` 单独断言，且每行的实际回复必须绑定本文件内一个可重算
   canonical SHA-256 的记录对象或 `QRY`/`NZ`/`FC`/`VR` 既有行，G5 的 `DOM`/`TSK` 判定不得把无机检绑定的行或缺口行当作已实测证据。
7. **`采用` 是 `SBC-08` 成功行的封闭补值（对契约缺口的行文裁定，交评审面板复核）**：§2.1 的 `实际回复类别` 枚举
   （澄清 / 合格备选 / 公开摘要 / 停止，加本文件第 2 条的第四态）全部是**降级或停止**面的取值，没有一个是 §4.2 与 §2.2 6(c)
   要求的「已授权源可返回该季度 ⇒ 记正常成功行」。对 `SBC-08` 而言：取 `公开摘要` 或 `合格备选` 会虚报一次未发生的降级（且 `cmd-03`
   要求这两态引用 `queries.md#单指标单源` 的既有采用行，而本轮 `SRC` 行的采用源仍是 wind-finance 的 `QRY-01`，不存在该源该期间的采用裁决行），
   取 `缺口-未重现` 正是 §2.2 6(c) 明文禁止的「把源可返回的历史数据报为不可得」。因此本行取 §4.1 ⑤ 既有词汇中的 `采用`，并由 `cmd-03` 把它
   锁死为**只有 `SBC-08` 可取**、且引用的记录对象 `字段清单` 必须是字段名而非「无…」（即机检证明源确实返回了数据，该记录本身另受 canonical
   SHA-256 与 RunWindow 边界约束）；其余八行取该值一律非零退出。该补值不改动 §2.1 的四个既有取值，也不引入第二套列定义。
8. **round3 清单的换行口径（原始形态事实，随件转录）**：`round3/SHA256SUMS.txt` 是 CRLF，按 round-2 的命令形态直跑
   `sha256sum -c SHA256SUMS.txt --strict` 报 `WARNING: 6 listed files could not be read` 且 exit=1——这是清单行尾 `\r`
   被并入文件名造成的假失败，不是缺件或篡改。本节点改用 `tr -d '\r' < SHA256SUMS.txt | sha256sum -c --strict -` 复核，6/6 OK、exit=0；
   round-2 同名件为 LF，直跑即过。本文件的 round3 文件级锚点按**归一后**的口径实测（对象级 canonical SHA-256 与该换行问题无关，三条 3/3 全等）。
