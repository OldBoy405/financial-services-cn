# CR4 需求｜其余能力与 phase-1 收口

**阶段：**phase-1／原任务 4 后半＋原任务 5 的发布就绪检查。**目的：**在真实任务中验收剩余六项能力，复核 M1 三项仍然有效，累计 **9/9 留痕通过**，完成本机自用验收；发布就绪检查不是公开上架或市场审核。

## 进入条件：必须是已验收的产物/能力

- [CR1《基线与专家包》](2026-09-26-workbuddy-equity-research-cr1-baseline-package.md)：目标机可安装且九项可正确路由的源可重建专家包、九项旧命令/技能的等价映射表、`ACCEPTANCE.md` 记录位，而非仅有九个技能文件名。
- [CR2《数据与授权》](2026-09-26-workbuddy-equity-research-cr2-data-authorization.md)：六项各自必需的数据域已获授权、在目标机真实取数并有来源/时效证据；无权限/过期/冲突的降级测试、本机重装步骤已验收。缺哪个数据域，哪个完整版能力继续阻塞。
- [CR3《研究主链 M1》](2026-09-26-workbuddy-equity-research-cr3-research-chain-m1.md)：`earnings`、`initiate`、`model-update` 三项已有用户裁决通过、真实文件及跨会话接续证据；验收时复核其依赖未被后续包/数据变更破坏，不把旧的 3/9 自动加到新包版本。

## 范围与交付

1. **六项真实任务，逐项保留原命令的补充要求。**每项按 CR1 已验收的等价映射表核对相应 `commands/*.md` 与技能，不能仅凭路由成功签收：

   | 入口／技能 | 实际验收重点（在映射表要求之外） |
   | --- | --- |
   | `/screen` → `idea-generation` | 全市场筛选范围、条件、可复核候选列表与来源、空结果和条件调整；说明数据覆盖与时效，不把样例列表冒充全市场扫描。 |
   | `/catalysts` → `catalyst-calendar` | 催化剂日期、来源、日历/公告校验、时区或市场差异、失效事件更新；未知日期不写成确定日程。 |
   | `/morning-note` → `morning-note` | 所覆盖股票的隔夜事件、市场反应、新闻/公告及截至时点；无实时或获许可数据时标明覆盖缺口，历史日期与次日反应不得冒充实时事件。 |
   | `/earnings-preview` → `earnings-preview` | 指定公司的财报前瞻，核实披露日、已知业绩预告/快报及券商预期的来源/期间；没有一致预期则标缺口，不填“市场预期”。 |
   | `/sector` → `sector-overview` | 行业格局、可比公司、规模/币种/时点口径、数据时效与引用，文件要求按旧命令映射；不能以单只股票代替行业结论或混用币种/期间。 |
   | `/thesis` → `thesis-tracker` | 原论点及其证据、反证、催化剂/风险和可找回的旧版本；跨轮更新要区分新增信息与旧观点，不能凭空改写前次结论。 |

2. **逐项正例、负例与文件核验。**六项各自安排真实 A股/港股研究请求、CN/EN 问法及可复核来源；测试适用的错误代码、指定历史季度/日期、空结果、无权限、来源冲突和时效过期，并至少一次美股个股请求，验证只用公开面且明确提示不接入美系机构数据源。每项按自身产物要求核对结果文件可下载、可打开与内容完整；若数据不足，只能输出标明缺口的公开摘要或停下，不得把摘要签作完整版。对无法适用的负例注明不适用理由，不以空白代替结果。
3. **发布就绪检查（phase-1 范围内）。**用目标 WorkBuddy 实际认可的 `expert-manager` `validate_expert.py`/`register_expert.py` 或同版本等价流程校验、安装/注册由源导出的包；记录客户端版本、校验器版本、包版本和校验结果。运行时目录 `~/.workbuddy/plugins/marketplaces/my-experts/` 只作本机安装位置，包源仍在仓库。检查包无 `.mcp.json`、美系 MCP 声明、真实凭据、开发机全局配置或绝对路径依赖；westock CLI、neodata 云服务及各连接器对未来安装用户有明确安装/授权说明。按已获授权的本机范围核对品牌、开源许可、合作方内容、数据引用/再分发条款和研究免责声明，列出公开分发仍需确认的事项；**公开上架许可批准不作为本机自用验收条件，但若现有使用本身未获许可，受影响能力不能通过。**
4. **版本与回归。**任何技能、权限、连接器或文件工具路径变更，先提高包版本并重导出，再对受影响的原三项及新增六项重做相关正例/负例、取数、文件和本机重装核验；在 `ACCEPTANCE.md` 中保留旧版与新版裁决及失效原因。工作流 9/9 与市场审核分成两个独立状态。

## 交付物

- 六项各自的真实研究请求、原始来源/日期/权限记录、结果文件或回复、适用负例、下载打开核验与用户逐项裁决；更新 `workbuddy-experts/equity-research/ACCEPTANCE.md` 的九项汇总。
- 本机重装、最终包版本与 WorkBuddy 校验/注册证据；发布就绪检查清单（依赖与授权路径、素材/许可/再分发/免责声明预检、待 phase-2 解决的公开分发风险）。
- 受影响的 M1 重测记录及新的源→导出包一致性证明。宣传措辞仅列已通过的工作流，未 9/9 不使用“原插件全功能迁移”“功能无降级”。

## 验收标准

- 六项分别在真实任务下符合旧命令和技能的等价要求，能说明覆盖、时效与出处；正例与适用负例留痕，错误、空结果、无权限及冲突不会生成看似完整的研究结论；每项由用户裁决通过。
- 三项 M1 的先前通过证据仍对应当前包/数据环境；变更导致失效的项先重测。`ACCEPTANCE.md` 对九项都有日期、测试问法、产物链接、负例结果、当前包版本与用户裁决，**当前可复现的通过项恰为 9/9**，无“待测/仅摘要”混入通过计数。
- 从仓库源重导、校验、安装、取数与产物交付可在本机复现；包不依赖开发机私配，依赖安装与授权路径有文档。发布就绪清单完成预检，公开分发尚待许可/审核的项目明确列为 phase-2 待办。
- 最终裁决只可称“phase-1 本机自用 9/9 完成”；不能声称非开发者已安装、市场已提交或审核通过。

## 不包含／后续入口

不包含面向第二用户的干净环境安装与九项复测、合规许可的**公开分发批准**、市场提审/审核、其他金融领域迁移。上述事项待条件成熟后单立 phase-2 第 5 个 CR 并写独立需求文档；本 CR 的发布就绪材料可作输入，但不自动满足其验收。
